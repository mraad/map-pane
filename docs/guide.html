map-pane Manual

map-pane is a live web map. An agent controls the map from the terminal. You can control it from the terminal too. This manual tells you how to install, start, use and stop the map.

1What map-pane is

map-pane shows a map that is built on the ArcGIS Maps SDK for JavaScript 5.2.2.

Headless Chrome draws the map. A terminal pane shows the map with Kitty graphics. The pane sends your mouse and keys to the map. A browser tab can show the same map.

An agent changes the map with a command line tool, mappane/bin/map-command. The agent can be Claude Code, Codex or Pi. One skill, map-pane, tells each agent how to use the tool.

The map can do these tasks:

  • Add data: GeoJSON (file, URL or inline), GeoPackage, GeoParquet, CSV, feature services, map services, tile, vector tile and imagery layers, and portal items.
  • Style data: renderers, labels and filters.
  • Move the view: to a place or an address, to coordinates, or to a layer.
  • Change the basemap.
  • Sign in to a portal and save the map as a private web map item.
  • Save a PNG screenshot.
  • Run JavaScript in the map page.
Note

Version 0.5.0 removed the Claude Code mod. The plugin mappane, the command /map and the tools mcp__mappane__* do not exist now. Claude Code uses the skill, like Codex and Pi.

5Start the map

All paths in this manual start at the repository folder.

Start the map in a Ghostty split

  1. Open a Ghostty terminal in the repository folder.
  2. Type mappane/bin/map-pane --split.
  3. On the first run, let macOS allow your terminal to control Ghostty.
  4. Wait until the map shows in the new split. This takes approximately 5 seconds.
  5. Type mappane/bin/map-command extent. The command prints the current view when the map is ready.

Start the map in a browser

  1. Type mappane/bin/map-pane --browser.
  2. The launcher opens the map page in the default browser and prints {"url": ...}.
  3. Type mappane/bin/map-command extent to make sure that the map is ready.
mappane/bin/map-pane --split   # open a split to the right of the terminal that ran it
mappane/bin/map-pane --browser # open the map in the default browser
mappane/bin/map-pane           # run in the current terminal
Caution

Do not let an agent run mappane/bin/map-pane without --split or --browser. The pane then takes over the current terminal in raw mode.

How the launcher finds a bridge

  • The launcher first looks for a running bridge of your user. If one answers, the pane shows that map.
  • If no bridge answers, the launcher starts a bridge on a free port.
  • With --browser, a bridge that the launcher starts runs in the background. It continues after the launcher stops.

Set the start view

Set these variables on the launcher. They apply only to a bridge that the launcher starts. A bad value stops the launcher.

MAP_PANE_CENTER=51.5074,-0.1278 MAP_PANE_ZOOM=10 mappane/bin/map-pane --split
VariableDefaultValue
MAP_PANE_BASEMAPosmA legacy basemap id.
MAP_PANE_CENTERnonelatitude,longitude
MAP_PANE_ZOOM30 to 23. Needs MAP_PANE_CENTER.
MAP_PANE_EXTENTthe worldxmin,ymin,xmax,ymax in longitude and latitude. Overrides center and zoom.

7Stop the map

Stop a split

  1. Click in the map split.
  2. Push Ctrl+C.

The pane restores the terminal and stops its Chrome. If the launcher started the bridge, the launcher stops the bridge too. A bridge that was already running continues. Ghostty closes the split.

Stop a browser map

  1. Type mappane/bin/map-pane --close.
  • The command stops the bridge that --browser started.
  • The command closes the map tabs in Google Chrome. Tabs in other browsers stay open and show that the connection is lost.
  • If --browser did not start a bridge, the command stops nothing and exits with status 1: no map was opened with --browser.

8Map commands

Type the commands in a terminal that is not the map split. Each command prints JSON and exits with status 0. A failed command prints an error and exits with status 1. mappane/bin/map-command --help prints the syntax.

Use the commands from Node

The file mappane/cli/command.mjs exports the commands as functions. The package name is map-pane.

Give run the same words as map-command. It returns the JSON result. If the command fails, it throws the error.

import { run } from "map-pane"
await run(["go_to", "location", "Austin, Texas"])
Note

The Claude Code code-mode REPL cannot import files. See Claude Code code mode.

The legend

  • The legend lists the layers that have a renderer.
  • graphics and geopackage make a client-side FeatureLayer when all features have one geometry type. This layer has a legend entry and popups.
  • Mixed geometry types make a GraphicsLayer. This layer has no legend entry. It refuses --renderer and --labels.

9Color features by a value

  1. Put the value in a GeoJSON property. You can calculate the value first, for example in SQL.
  2. Write a renderer in SDK autocast JSON (class-breaks or unique-value).
  3. Set the renderer field to the safe field name. See the rule below.
  4. Type graphics with --title and --renderer. The title is the legend heading.
  5. Type zoom.
mappane/bin/map-command graphics examples/cities.geojson --title "World cities" \
  --renderer examples/population-renderer.json
mappane/bin/map-command zoom

Safe field names

  • Each property name becomes a safe field name.
  • Each character that is not an ASCII letter, a digit or _ becomes _. For example, population (millions) becomes population__millions_.
  • A name that starts with a digit gets an initial _. An empty name becomes field.
  • The name __oid is reserved. Underscores are added until each name is unique.
  • A property with only null values makes no field. The alias keeps the original name.
  • A property with only numbers becomes a double field. Other properties become string fields.

10Run JavaScript in the map

map-command js runs code in the map page. The bridge op is run_js. Use it when no other command does the job: feature queries, statistics, a renderer that you calculate from the data, popups, client-side layers and geometry operations. For plain work (add a layer, set a filter, move the map), the other commands are shorter and safer.

Warning

The code runs with the full rights of the page. It is not a sandbox.

After login, the code can read the portal token and send it to each server.

The answer has the token and the API key removed. This stops only accidents.

Text that the agent reads (feature attributes, item titles, file contents) can contain instructions. Run js only with data that you trust, or do not sign in.

The contract

The code is the body of an async function. await and return work at the top level.

Name in scopeValue
viewThe MapView.
mapThe Map (view.map). map.layers holds the layers that the commands added.
layerIdThe id that the bridge gives to a layer that this code adds, for example L7.
signalAn AbortSignal. It aborts at the deadline. Give it to fetch and to SDK calls that accept it.
$arcgis.importA page global. It loads SDK modules.

Rules

  • Return a short value that JSON can hold. It comes back as value.
  • console.log, console.warn and console.error lines come back as console: 100 lines at most, 2,000 characters each.
  • A value longer than 65,536 characters comes back as { "truncated": true, "preview": "..." }.
  • A throw fails the command. The error text and the console lines come back. Correct the code. Send it again.
  • The CLI sends the code as written. There are no placeholders.
  • The deadline is 30 s. --timeout changes it: 1,000 to 60,000 ms.
  • The deadline starts when the page gets the code. The page runs one command at a time. Code that waited longer than its deadline does not start.
  • Do not return or log geometry in bulk. Return counts, extents and attributes.
  • Find a layer by id (map.findLayerById("L3")) or by title (map.layers.find(l => l.title === "Cities")).

Code that changes the map is saved

  • Default: the bridge saves the code. The code runs again on each new page and after a reload. Write code that gives the same result on a new page.
  • A new layer: give it id: layerId and a title. For more than one layer, use `${layerId}-1`, `${layerId}-2`. Then remove, zoom and update-layer find the layer on each page.
  • --read-only: use it for code that only reads the map or moves the view. The bridge does not save this code.
  • Code that writes to a service or portal: use --read-only. Keep only one map page open. Each open page runs the code. Saved code runs again on each new page.
  • Code that fails is not saved. Code that passed the deadline is a failure. It can still complete on its page. Examine the map before you send the code again.
  • Code that blocks the page (a loop that does not end) gets no answer. After 65 s the command fails, and the bridge does not save the code.
  • clear removes the saved commands and the layers.

Use from the shell

# Inline code. Use single quotes, so that the shell does not change the code.
mappane/bin/map-command js 'return map.layers.map(l => ({ id: l.id, title: l.title })).toArray()' --read-only

# A file. The name must end in .js or .mjs.
mappane/bin/map-command js ./size-by-population.js

# Standard input, with a 60 s deadline.
cat query.js | mappane/bin/map-command js - --read-only --timeout 60000

The answer is { "value": ..., "console": [...] }. console is absent when the code logged nothing. value is absent when the code returned nothing.

Example: statistics (read only)

const layer = map.layers.find(l => l.title === "Cities")
const { features: [row] } = await layer.queryFeatures({
  where: "1=1",
  outStatistics: [
    { statisticType: "count", onStatisticField: "name", outStatisticFieldName: "cities" },
    { statisticType: "max", onStatisticField: "population__millions_", outStatisticFieldName: "largest" },
  ],
})
return row.attributes

Answer: { "value": { "cities": 20, "largest": 37 } }

Example: a new layer from a geometry operation

This code makes a 300 km geodesic buffer around the three largest cities. The new layer gets layerId.

const [GraphicsLayer, Graphic, buffer] = await $arcgis.import([
  "@arcgis/core/layers/GraphicsLayer.js",
  "@arcgis/core/Graphic.js",
  "@arcgis/core/geometry/operators/geodesicBufferOperator.js",
])
await buffer.load()
const cities = map.layers.find(l => l.title === "Cities")
const { features } = await cities.queryFeatures({
  where: "1=1", orderByFields: ["population__millions_ DESC"], num: 3, outFields: ["name"], returnGeometry: true,
})
const rings = new GraphicsLayer({ id: layerId, title: "300 km around the 3 largest cities" })
const symbol = { type: "simple-fill", color: [228, 87, 46, 0.2], outline: { color: "#e4572e", width: 1 } }
for (const f of features) {
  rings.add(new Graphic({ geometry: buffer.execute(f.geometry, 300, { unit: "kilometers" }), symbol, attributes: f.attributes }))
}
map.add(rings)
return { layerId, rings: rings.graphics.length, cities: features.map(f => f.attributes.name) }

12Sign in to a portal

login uses OAuth 2.0 with an authorization code and PKCE. The client ID needs no secret. The map pages keep the token and refresh it. The CLI does not print the token. The bridge does not log or save the token.

  1. In the portal, open the OAuth credentials of your app.
  2. Add the redirect URI http://127.0.0.1:8766/.
  3. Set MAP_PANE_CLIENT_ID, or use --client-id.
  4. Set MAP_PANE_PORTAL_URL, or use --portal-url. The default is https://www.arcgis.com.
  5. Start the map.
  6. Type mappane/bin/map-command login.
  7. Sign in on the page that opens. You have 5 minutes.
MAP_PANE_CLIENT_ID=<client-id> mappane/bin/map-command login
mappane/bin/map-command basemap arcgis/navigation
mappane/bin/map-command save-webmap "Austin sites"
  • login prints the sign-in URL on standard error. Open the URL yourself if no browser opens.
  • Only one login can wait at a time, because it listens on port 8766. Use --redirect-uri or MAP_PANE_REDIRECT_URI for a different loopback port.
  • Pages that open later get the sign-in from the bridge. After a bridge restart, sign in again.
  • A save runs on one page only. If that page disconnects during the save, examine the portal before you try again. The item can exist already.

Use the arcctl sign-in

If you use arcctl, you can sign in one time. The map then uses the arcctl session.

  1. Type arcctl login --portal <portal-url> --client-id <client-id>.
  2. Start the map.
  3. Type mappane/bin/map-command login --arcctl.
  • --arcctl reads the file config.json in the arcctl folder. The folder is ARCCTL_CONFIG_DIR, or ./.arcctl if it exists, or ~/.arcctl.
  • map-pane only reads the file. It does not write the file. It does not print the token.
  • The file must belong to you. Only you can read it (mode 600).
  • Use an OAuth arcctl login. A --generate-token session cannot renew, so --arcctl refuses it.
  • The token goes only to the portal that issued it. If --portal-url names a different portal, --arcctl refuses.
  • The map pages renew the token in memory. After arcctl logout or a new arcctl login, type login --arcctl again.
  • The sign-in goes from arcctl to the map only. The map does not give its token to arcctl.

13Agents

The agent reads the skill. Then the agent runs scripts/map-command from the skill folder. The agent can query data (for example with DuckDB), write GeoJSON and a renderer, and send them with graphics. For questions about data that is on the map, the agent writes code for js.

Claude Code

  • Claude runs the CLI with its shell tool. Claude asks before each new command.
  • To stop the prompts, allow the CLI one time in /permissions, for example Bash(/path/to/map-pane/.agents/skills/map-pane/scripts/map-command:*).

Claude Code code mode

In code mode, Claude writes JavaScript and runs it in the REPL tool. One script can send many map commands and read each result. This uses fewer turns than one shell call for each command.

The REPL cannot import files, open sockets or use the network. The script calls map-command through $.

  1. Put the helper below in the first script. It stays for the session.
  2. Call map with the words of a command. The result is the JSON object.
  3. Wait for each command that changes the map before you send the next. Do not send them together: the bridge gives layer IDs in order of arrival.
  4. Use the layer ID from each result in the next commands.
const S = "/path/to/map-pane/.agents/skills/map-pane/scripts"
const parse = (r) => {
  if (r.exitCode) throw new Error(r.stdout.trim())
  const out = r.stdout, start = out.search(/^[[{]/m) // stderr is merged: skip notes (login URL) before the JSON
  return start < 0 ? out : JSON.parse(out.slice(start))
}
const map = async (...argv) => parse(await $`${S}/map-command ${argv}`.nothrow())
await map("go_to", "location", "Florence, Italy")
const { layers } = await map("graphics", "/path/to/cities.geojson", "--title", "Cities")
await map("zoom", layers[0].id)
  • $ quotes each value as one argument. Place names, JSON and filters need no shell quotes.
  • The REPL joins stderr to stdout. The helper skips the notes before the JSON, for example the sign-in URL of login.
  • $ has no standard input in the REPL. Write data to a file with write(), then give the path to graphics.
  • Give a renderer or labels as JSON.stringify(object).
  • Put the code for js in a plain string. A template string in the REPL changes ${...} before the page gets the code.
  • To look at the map, run map("screenshot", path) and then Read({ file_path: path }).
Note

Node code can import the same commands: import { run, connect } from "map-pane". The full guide, with recipes, an example and the API, is docs/code-mode.md.

Example: four cities and a geodesic line

Give Claude this request:

“Create markers in Tokyo, Dubai, Florence, and San Francisco, and create a geodesic line between them. Color-code the one in Dubai red and all the others blue.”

Claude can do the task with one script. The script calculates the points of the line, because the SDK draws a GeoJSON line straight on the map. The script uses the map helper above. Change /path/to/scratchpad to a folder that you can write to.

const cities = [["Tokyo", 35.6762, 139.6503], ["Dubai", 25.2048, 55.2708],
  ["Florence", 43.7696, 11.2558], ["San Francisco", 37.7749, -122.4194]]
const rad = Math.PI / 180
const vec = (lat, lon) => [Math.cos(lat * rad) * Math.cos(lon * rad), Math.cos(lat * rad) * Math.sin(lon * rad), Math.sin(lat * rad)]
const greatCircle = (a, b, n = 64) => {
  const p = vec(a[1], a[2]), q = vec(b[1], b[2])
  const d = Math.acos(p.reduce((s, x, i) => s + x * q[i], 0))
  return Array.from({ length: n + 1 }, (_, k) => {
    const s1 = Math.sin((1 - k / n) * d) / Math.sin(d), s2 = Math.sin((k / n) * d) / Math.sin(d)
    const [x, y, z] = p.map((c, i) => s1 * c + s2 * q[i])
    return [Math.atan2(y, x) / rad, Math.atan2(z, Math.hypot(x, y)) / rad]
  })
}
const line = cities.slice(1).flatMap((c, i) => greatCircle(cities[i], c).slice(i ? 1 : 0))
// shortcut: a leg that crosses the antimeridian jumps 360° in longitude; split it into a MultiLineString then.

const dir = "/path/to/scratchpad"
await write(`${dir}/route.geojson`, JSON.stringify({ type: "Feature", properties: { route: "Tokyo - Dubai - Florence - San Francisco" },
  geometry: { type: "LineString", coordinates: line } }))
await write(`${dir}/cities.geojson`, JSON.stringify({ type: "FeatureCollection", features: cities.map(([name, lat, lon]) => ({
  type: "Feature", properties: { name, color: name === "Dubai" ? "red" : "blue" }, geometry: { type: "Point", coordinates: [lon, lat] } })) }))

const marker = (color) => ({ type: "simple-marker", color, size: 12, outline: { color: "white", width: 1.5 } })
await map("graphics", `${dir}/route.geojson`, "--title", "Geodesic route",
  "--renderer", JSON.stringify({ type: "simple", symbol: { type: "simple-line", color: "#333333", width: 2 } }))
const { layers: [pts] } = await map("graphics", `${dir}/cities.geojson`, "--title", "Cities",
  "--renderer", JSON.stringify({ type: "unique-value", field: "color", uniqueValueInfos: [
    { value: "red", label: "Dubai", symbol: marker("#d62728") },
    { value: "blue", label: "Tokyo, Florence, San Francisco", symbol: marker("#1f5bd6") }] }),
  "--labels", JSON.stringify({ labelExpressionInfo: { expression: "$feature.name" }, labelPlacement: "above-center",
    symbol: { type: "text", color: "black", haloColor: "white", haloSize: 1.5, font: { size: 12, weight: "bold" } } }))
await map("zoom")
pts   // { id: "L3", title: "Cities", type: "feature", graphics: 4 }

The script adds the line first. Thus the markers are on top of the line.

Codex

The Codex workspace-write sandbox blocks the map socket with connect EPERM. Allow the socket:

codex exec -s workspace-write -c sandbox_workspace_write.network_access=true '$map-pane list the basemaps'
  • The same setting lets login listen on its loopback redirect and reach the portal.
  • login waits up to 5 minutes. Give the agent a shell timeout of 300 seconds or more.
  • The sandbox also blocks a browser. --browser then prints could not open a browser and the URL. The map still runs. Give the URL to the user.

14Several maps

The CLI sends each command to the newest bridge of your user. To select a different map, set its socket on each command:

MAP_PANE_SOCKET="$(node -p 'require("os").tmpdir()')/map-pane-$(id -u)/command-<bridge-pid>.sock" \
  mappane/bin/map-command extent
  • mappane/bin/map-command --info prints the page URL of the map that the CLI uses.
  • If MAP_PANE_SOCKET is set and a command fails with ENOENT or ECONNREFUSED, that map stopped. Unset the variable.
  • Each bridge can have many pages open (panes, browsers). All pages of one bridge show the same map.

15The bridge

The bridge is one Node.js process. The launcher starts it on a free port (port 0) when no bridge answers. The bridge listens on TCP 127.0.0.1:<port> and on a Unix socket, <tmpdir>/map-pane-<uid>/command-<pid>.sock, mode 0600. The folder must be owner-only (mode 0700).

Endpoints

EndpointCallerPurpose
GET / and the page filespageThe page files, read one time at start. No other path is served.
GET /api/startpageThe start view from the MAP_PANE_* variables.
GET /api/infoCLI, launcher{url, pid, socket}
GET /eventspageServer-sent events: the page version, then reset, the log and the last view for a new page, then live commands. Ids are <epoch>:<n>, so a page that connects again gets only what it missed.
POST /cmd {op, args}CLISends a command to each page (save_webmap: one page only). The first ok answer is the result. An error is the result only when each page failed. 503 noPage when no page is open.
POST /ack, POST /statepageThe answer to a command, or a manual change, with the map state of the page. After a clear, earlier commands can still answer, and the bridge discards their snapshots.
POST /clearCLIEmpties the log, starts a new epoch, sends reset to each page, deletes inline GeoJSON files.
GET/HEAD /files/<uuid>/<name>pageA local file from a path argument. Range requests work for GeoParquet. HEAD sends headers without reading the file body.

Ops

OpLoggedNotes
add_graphic, add_layer, update_layer, remove_layer, reorder_layer, clear_graphics, set_basemapyesadd_layer feature uses Layer.fromArcGISServerUrl. A FeatureServer root becomes a group layer.
graphicsyesGeoJSON as client-side layers. One geometry type: FeatureLayer. Mixed: GraphicsLayer.
geopackageas graphicsThe bridge decodes it in an isolated child process (read-only SQLite) and logs a graphics op.
run_jsyes, except read-onlyPage deadline 30 s (1 to 60 s). Bridge deadline 65 s. Code that no page answered leaves the log.
go_to, screenshot, extent, zoom, save_webmap, get_basemap, list_basemapsnoRead the map or move the view.
loginnoCarries a token. The bridge keeps the most recently dispatched successful login in memory and sends it first to each new page.
resetn/aSent by the bridge. Removes all layers and restores the start basemap.
  • The bridge gives each logged layer the id L<n> (L<n>-<i> for a graphics op with many tables). The ids are the same on each page.
  • A command that timed out stays in the log, because a page can still complete it. A run_js command that timed out leaves the log, because it blocked its page.
  • A live command carries expiresAt, the bridge deadline. The page stops run_js code 2 s before that time.
  • A page that connects while a run_js command is pending does not get that command in its replay.
  • Inline GeoJSON and screenshots go to a temporary folder. The bridge deletes the folder when it stops.
  • The bridge hashes the page files into a page version. A page with a different version reloads itself.

16Security

  • TCP accepts only Host: 127.0.0.1:<bound port>. This stops DNS rebinding.
  • TCP refuses a foreign Origin and a cross-site Sec-Fetch-Site. This stops a cross-site POST. The page files stay open, so a link to the map still works.
  • When MAP_PANE_TOKEN is set, the TCP control endpoints /cmd and /clear need the header x-map-pane-token.
  • The Unix socket skips these checks. Only its owner can connect (mode 0600).
  • File URLs use random UUID keys. The bridge serves only files that a command gave.
  • The login token stays in page and bridge memory. It is not in the log or on the disk.
Warning

map-pane is for a computer with one user. GET /events, /state and /files need no token, because browsers cannot send one. A different local user can read the map and its files over TCP. After a login, a new /events connection also gets the token.

18Data rules and limits

SubjectRule
GeoJSONWGS84 (RFC 7946). A crs member is an error. The page corrects polygon ring order.
Failed layersThe page loads a layer before it adds the layer. A layer that fails does not change the map.
GeoPackageEach vector table is a layer. EPSG or WKT and Z are kept. M is dropped. Raster tiles, curves and undefined coordinate systems are refused. URL downloads stream to a temporary file. 64 MiB and 100,000 features at most.
GeoParquetA file with no crs gets OGC:CRS84.
Deadlines15 s for each command. 60 s to add data, for graphics and for save-webmap. 30 s for zoom and screenshot. 30 s for js code (60 s at most). 30 s each for a GeoPackage download and conversion. 15 s for Chrome startup.
ServicesA service must allow browser CORS access.
RepeatsCommands that add data are not idempotent. Examine the map before you repeat a command that timed out.

Known limits

  • Frames have CSS resolution. On a Retina display, map text is softer than in a browser.
  • Each frame is a full PNG. This is correct for a local terminal. It is slow on an SSH connection.
  • The pane sends arrow keys, Enter, Backspace, Tab, Escape and printable text. It does not send function keys or Control and Alt combinations.
  • Headless Chrome draws no pointer. Ghostty shows its own pointer.
  • --close closes tabs only in Google Chrome.
  • The log only grows. A removed layer stays in the log as an add and a remove.
  • GeoPackage tables go into the log as inline data.
